# IsiX review: up to 6.0.4 (16 Nov 2026)

Reviewed from the last recorded point (`a05084b6`, 16 Oct 2026) to
`087f2cd0f721` (IsiX 6.0.4, 16 Nov 2026): 17 commits. The generated list of
every commit and file by area is in `latest-isix.md`.

## What the review covered

SekhmetX's ported logic was taken from IsiX as it stood on 13 Nov 2026. The
commit recorded for that (`3e24831224b8`) no longer exists: IsiX's history was
rewritten upstream. The closest surviving commit is `aceba6ac9898` (13 Nov), so
the comparison that matters for ported code is `aceba6ac..087f2cd0`, which is
the 6.0.4 release commit. `porting/map.toml` now records `087f2cd0f721` for the
areas checked here and `aceba6ac9898` for the others.

Checked file by file: everything under `Modules/IsiXImaging/Sources`,
`Modules/IsiXGeometry/Sources` and `Modules/IsiXROI/Sources`, plus every IsiX
file a Rust source names as its origin. `IsiXGeometry` did not change.

Not checked line by line: the areas SekhmetX rebuilds instead of porting
(browser, 2D viewer, MPR and 3D windows, preferences), and areas not started
(networking, PET fusion, reports, plugins). Their changes are listed in
`latest-isix.md`.

## Ported in SekhmetX 0.5.5

| IsiX change | IsiX files | SekhmetX |
|---|---|---|
| A VOI LUT is applied to every frame. A frame lying wholly outside the table, or on its first entry, is uniform, not a sign of a corrupt table. | `VOILUTMapping.swift`, `DCMPix+FrameLoading.swift` | `src/imaging/voi_lut.rs`, `src/frame.rs` |
| With a rescale slope/intercept, the VOI LUT is entered by the rescaled value (PS 3.3 C.11.2.1.1) instead of being skipped. | same | same |

| Frames that all sit at one position are a cine, not a volume. | `SliceIntervalCorrection.swift` | `src/volume.rs` (`from_series_checked`) |
| Exponential slab-thickness slider with whole-millimetre stops. | `ThickSlabSliderScale.swift` | `src/imaging/slab_scale.rs`, slab slider in `src/ui/toolbar.rs` |

IsiX's tests for the VOI LUT and the slider scale were translated with the code.

## Already the same

- `SliceSpacingRegularity.swift` (moved into the module in 6.0.4): 10 % interval
  tolerance and half-pixel grid deviation along the slice normal. This is the
  rule `SliceRegularity::evaluate` in `src/volume.rs` already follows.

## Not ported, with the reason

| IsiX change | Why not now |
|---|---|
| Slab thick end is the whole volume (`volumeMaximum`) and slider tick marks | Slab sampling here is capped at 65 steps, so very thick slabs would skip voxels; the thick end stays at 50 mm. Recorded in `DEVIATIONS.md`. The function is ported for when the cap is lifted. |
| `SeriesConvolution.filterVolume` / `finishGreyVolume` | Filters a whole volume for the volume-rendering window. SekhmetX filters the displayed slice only. |
| Dose-grid frame origin along the grid normal (`DCMPix+FrameLoading`) | RT dose grids are not handled yet. |
| `ROILengthRatio.swift` (live ratio of two lengths) | New feature. Good candidate for the measurements work. |
| `ROIContourJoin.swift`, `ROIMissingGeneration.swift`, `ROIUndoQueuePolicy.swift` | Depend on named ROIs across slices, ROI interpolation and undo, which SekhmetX does not have yet. |
| `MPRZoomSync.swift` | SekhmetX already applies linked zoom; IsiX's rule (one reconstruction when a pinch ends) is about pinch gestures. |
| `RulerCalibration.swift` (calibrate spacing from a known length) | New feature. Useful for uncalibrated images. |
| `USRegion.swift` (ultrasound region calibration) | New feature. Needed for correct measurements on ultrasound. |
| `StenosisMeasurement`, `StenosisPlaque`, `VesselTube`, `CurvedPathSet`, `EndoscopyNavigation` | Vessel analysis on curved MPR; curved MPR is not started (`cpr`, P3). |
| `DocumentPagePolarity.swift`, `PresentationStateOverlay.swift`, `SettingsPropagation.swift`, `SliceStack.swift`, `SeriesConsistency.swift`, `VolumeRenderingOpening.swift`, `VolumeRevertSource.swift`, `ShadingValuesText.swift`, `VolumeViewButtons.swift` | Support code for IsiX windows that SekhmetX rebuilds differently or does not have (PDF/SR pages, GSPS, propagation between windows). |
